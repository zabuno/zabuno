Veri Modeli — DocType Şemaları

Frappe DocType'ları, ilişkiler, indeksler ve izin modeli. Mock veri yok; yalnızca yapı.

Varlık ilişkileri

Media Asset ──1:1── Media Source        (yüklenen ham dosya)
     │
     ├──1:N── Media Version             (normalize master; yeni politika → yeni version)
     │            └──1:N── Media Rendition   (profil × genişlik × format)
     │
     ├──1:1── Media Crop Intent         (focal + safe region + profil override child table)
     ├──1:N── Media Processing Job
     ├──1:N── Media Usage               (hangi DocType.field kullanıyor)
     └──1:N── Media Quality Report

Media Profile   (rendition reçetesi — veri)
Media Policy    (slot kuralları — veri)
Media Engine Settings   (Single, superadmin)
Media Storage Settings  (Single, superadmin — S3/CDN)

Media Source

Ham dosya kaydı: file_url, storage_backend, bytes, mime_real, mime_claimed, width, height, megapixels, dpi_x/y, colorspace, has_alpha, frames, duration, video_codec, audio_codec, bitrate, exif_stripped, uploaded_by, client_report (JSON: tarayıcının yaptığı işlemler). Asla değiştirilmez.

Media Version

Normalize master: version_hash (içerik hash'i, URL'lerde kullanılır), width, height, dpi (72), colorspace (sRGB), policy_snapshot (JSON — hangi politikayla üretildi), engine_version (pyvips/libvips sürümü), created_at. Politika veya crop değişince yeni version üretilir; eski version geçmiş için kalır.

Media Rendition

version, profile, width, height, format, bytes, quality, ssim, file_url, storage_backend, generation (eager/lazy), last_access_at, benefit_gate_passed. Unique index: (version, profile, width, format).

Media Crop Intent

focal_x, focal_y, safe_x/y/w/h, method (manual/smartcrop/center), algorithm, algorithm_version, confidence, approved_by_user, previewed_placements (JSON — simülatörde görülen yerleşimler), child table Media Crop Override: profile, x, y, w, h, method. Tüm koordinatlar 0–1 normalize (INV-10).

Media Profile

profile_key, label, aspect_ratio, widths (JSON dizi), formats (JSON), fit, quality_target, generation (eager/lazy), enabled. Kod değişmeden yeni profil eklenebilir.

Media Policy

Slot politikası (Faz 2 JSON şemasının DocType karşılığı): slot_key, roles, accept, require, master, quality, profiles (child), content_rules (child), on_violation, messages.

Media Processing Job

asset, job_type, queue, status, attempt, started_at, finished_at, duration_ms, peak_memory_mb, error_code, error_trace, idempotency_key.

Media Usage

asset, ref_doctype, ref_name, ref_field, profile_used, first_seen, last_seen. Öksüz dosya GC'sinin temeli.

Media Quality Report

asset, version, input_bytes, output_bytes, saving_ratio, ssim, vmaf, decisions (JSON — hangi kural neden uygulandı), warnings.

Media Engine Settings / Media Storage Settings (Single, superadmin)

Bkz. Faz 5. Bu iki Single DocType satıcı ve alıcı rollerine okuma dahil kapalıdır.

T-041Crop intent veri modeli ve öncelik zinciriBackendBağımlılık: T-040
Amaç

Kırpma kararının nasıl seçildiğini tek bir yerde, test edilebilir şekilde uygulamak.

Öncelik zinciri
1. Profile-specific manual crop override
2. Safe region + focal point (kenar sıkıştırmalı)
3. Global focal point
4. Smart crop önerisi (güven skoru ≥ eşik)
5. Merkez kırpım (fallback)
Kabul kriterleri
  • resolve_crop(asset, profile) → window fonksiyonu öncelik zincirini uyguluyor.
  • Tüm koordinatlar oran cinsinden; kaynak yeniden normalize edilse bile görsel sonuç aynı (INV-10 property testi).
  • Pencere daima kaynak sınırları içinde (clamp) ve istenen orana tam uyuyor.
  • Smart crop önerisi approved_by_user=0 iken de kullanılıyor ama UI'da "öneri" olarak işaretleniyor.
Geliştirici prompt'u
media_engine/image/crop.py içinde resolve_crop(asset, profile) -> CropWindow yaz; önce tests/test_crop.py (önce test).
Öncelik zinciri: 1) profil override 2) güvenli alan + odak noktası 3) genel odak noktası 4) smartcrop önerisi (confidence >= eşik) 5) merkez.
Algoritma (odak noktalı cover): hedef orana göre taban bölge içinde en büyük pencereyi bul, odak noktasını merkeze al, sonra pencereyi taban bölge sınırlarına sıkıştır (clamp).
Testler:
- özellik testi (hypothesis): rastgele kaynak boyutu/oran/odak için pencere daima sınırlar içinde ve oranı hedefle %0,5 tolerans içinde
- INV-10: kaynak 2 kat küçültülüp aynı oran tabanlı intent uygulandığında, üretilen görüntü (normalize edilmiş) aynı kadrajı verir
- öncelik zinciri: her seviye için bir test; üst seviye varken alt seviyenin kullanılmadığını doğrula
- sıkıştırma: odak köşede olduğunda pencere dışarı taşmaz
Not: bu fonksiyon docs/simulator.html içindeki cropWindow() ile AYNI matematiği uygulamalıdır; simülatör çıktısı ile backend çıktısını karşılaştıran bir altın test yaz (aynı girdi -> aynı pencere).
T-042Dedup, versiyonlama ve içerik hash'iBackendBağımlılık: T-040
Kabul kriterleri
  • Aynı SHA-256 iki kez yüklenirse ikinci yükleme yeni dosya yazmıyor, mevcut asset'e bağlanıyor.
  • Eşzamanlı aynı-dosya yüklemesinde yarış koşulu yok (unique index + retry testi).
  • version_hash = f(source_hash, policy_snapshot, crop_intent, engine_version); girdilerden biri değişince değişiyor.
  • Rendition URL'i version_hash taşıyor (INV-09); içerik değişmeden URL değişmiyor.
  • pHash ile "benzer görsel" tespiti çalışıyor ve uyarı üretiyor.
Geliştirici prompt'u
Tekilleştirme ve sürümleme yaz: media_engine/core/dedup.py, media_engine/core/versioning.py + testler (önce test).
1) Yükleme sırasında akış hâlinde SHA-256 hesapla (dosyayı tümüyle belleğe almadan). Aynı hash varsa yeni Media Source yazma, mevcut asset'e referans ver ve kullanıcıya "bu dosya zaten kütüphanenizde" bilgisi döndür.
2) Eş zamanlı aynı dosya yüklemesi testi: iki paralel finalize çağrısı; tek asset oluşmalı, ikincisi mevcut kaydı döndürmeli (benzersizlik ihlalini yakalayıp idempotent dön).
3) version_hash = sha256(source_hash + canonical_json(policy_snapshot) + canonical_json(crop_intent) + engine_version). Girdilerden biri değişince değişmeli, hiçbiri değişmeden aynı kalmalı (test).
4) Rendition dosya yolu: /files/media/{asset}/{version_hash}/{profile}-{width}.{ext}. Cache-Control: public, max-age=31536000, immutable.
5) pHash (algısal hash) hesapla ve aynı üründeki görsellerle mesafeyi ölç; eşik altında "tekrar görsel" uyarısı üret.
Testler INV-06 (idempotency) ve INV-09 (değişmez URL) değişmezlerini kanıtlamalı.
T-043Kullanım takibi (Media Usage) ve öksüz dosya tespitiBackendBağımlılık: T-040
Kabul kriterleri
  • Bir asset bir DocType alanına bağlandığında/çözüldüğünde Usage kaydı güncelleniyor.
  • Hiçbir Usage kaydı olmayan ve N gün eski asset'ler "öksüz" raporunda listeleniyor.
  • Öksüz asset otomatik silinmiyor; yalnızca rapor + superadmin onayıyla silme.
  • Rendition erişim damgası (last_access_at) güncelleniyor (örnekleme ile, her istekte değil).
Geliştirici prompt'u
Kullanım takibi yaz: media_engine/core/usage.py + testler.
1) doc_events ile: bir DocType'ın Attach/Attach Image/Link alanı bir media asset'e işaret ettiğinde Media Usage kaydı oluştur/güncelle; referans kaldırılınca kaydı kapat (last_seen).
2) Manifest servis edildiğinde profile_used bilgisini kaydet (hangi profil gerçekten kullanılıyor) — örnekleme ile (%1) veya toplu tampon ile yaz; her istekte veritabanına yazma.
3) Rendition.last_access_at güncellemesi: CDN/nginx erişim log'larını işleyen günlük bir zamanlanmış iş VEYA uygulama katmanında örnekleme; hangisini seçtiğini ve maliyetini docs/ altında yaz.
4) Öksüz tespiti: Usage kaydı olmayan, N günden eski, legal_hold=0 asset'leri raporla (Media Orphan Report). OTOMATİK SİLME YOK; superadmin onay akışı.
5) Testler: bağlama/çözme senaryoları, öksüz raporunun doğruluğu, silinmemesi gerekenlerin (legal_hold, yeni yüklenen) raporda çıkmaması.
